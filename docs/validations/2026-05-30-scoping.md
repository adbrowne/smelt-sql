- ❌ **Run-pipeline does NOT gate on scoping diagnostics (BUG-019, BUG-006 class).** The scoping codes above all fire in the smelt-db `file_diagnostics` (LSP) path, but `smelt type`/`build`/`run` never run that pass. A cyclic-CTE function (`examples/scoping_probe/functions/cyclic.sql`) that `file_diagnostics` flags `CteCycle` is spliced verbatim into the model by `smelt build` and fails downstream in DuckDB (`Catalog Error: Table with name b does not exist`) with exit 1 — a low-level error far from the cause — instead of the spec-mandated §"CTE rules" `CteCycle` anchored at the declarations. Logged **BUG-019** (needs-review). Same asymmetric-discovery class as BUG-006/011/015.
- ❌ **PASSING-supplied fragment parameters are dropped by the run-pipeline expander (BUG-018, BUG-013 class).** The block `PASSING <name> AS (<body>)` call syntax type-checks clean in the LSP/`function_body_check.rs` path, but `crates/smelt-runtime/src/compile.rs::substitute_params_with_named` (`:134`) only consumes positional + named (`=>`) arguments; PASSING bindings are never collected. The fragment parameter is left as its bare name (`WHERE pred`) or its default (`()`) in the emitted SQL, producing invalid SQL at `smelt build`. The repo's own demo `examples/functions_demo/models/rollup_with_passing.sql` reproduces this (`()` leftover → DuckDB parser syntax error). Logged **BUG-018** (needs-review).

### Semantics drift
- ❌ **§1 Strict-by-default / §14 family-rejection — cross-family binary arithmetic is NOT rejected.** `SELECT 42 + '3'` infers `{bad: SMALLINT}` (probe: `smelt type`), but spec §14 row 1 mandates `Unknown` + `TypeMismatch`. The strict rule DOES fire for sibling surfaces — `SELECT [1,'hello']` → `UNKNOWN` and `SELECT 1 UNION SELECT 'a'` → `UNKNOWN` (both correct) — so the gap is specific to the binary-arithmetic inference path. Logged as **BUG-017** (needs-review). See `docs/bug-hunt/2026-05-30-findings.md`.
- ✅ §3 Integer division truncating — `SELECT 7 / 2` → `SMALLINT` (integer family preserved, no widening to Double). Consistent.
- ✅ §4 String unification — `SELECT UPPER('abc')` → `TEXT`. Consistent.
- ✅ §5 Canonical built-in returns / aggregate non-nullability — `SELECT COALESCE(SUM(x),0)` → `BIGINT` (SUM(int)→BigInt, COALESCE→non-null). Consistent.
- ✅ §1 mixed array literal — `[1,'hello']` → `Unknown`. Consistent.
- ✅ §1 UNION incompatible families — `1 UNION 'a'` → `Unknown` per column. Consistent.

### Surface drift

- ✅ **Source YAML shape** — `description`, `columns`, `columns[].name`, `columns[].nullable`, `columns[].description`, `name:` override, `tags:` all parsed (`crates/smelt-core/src/sources.rs:102-218`). Forbidden `materialization:` detected (`sources.rs:169-171`); `columns:` required (`sources.rs:174`); `name:` format checked (`sources.rs:177-181`); unknown column type detected (`sources.rs:189-192`).
- ✅ **Filesystem layout / addressing** — discovery walks `paths:`, strips scan-root, sidecar tiebreaker on sibling `.csv` (`sources.rs:228-297`); `address_segments` correct.
- ✅ **`timeseries:` on a source** — grammar hosted (parsed by the shared frontmatter path; declared in `timeseries.md`).
- ❌ **Default `smelt.<path>` → `<db_schema>.<db_table>` mapping diverges from spec.** Spec §"Filesystem layout" (and `docs-site/docs/reference/sources-yml.md:22,64`) say the default is `<target_schema>.<path-joined-by-_>` — e.g. `smelt.sources.raw.users` → `main.sources_raw_users`. The code instead emits the **last two address segments as `<schema>.<table>`** — `raw.users` (`crates/smelt-runtime/src/compile.rs:558-589`, esp. 574-585). `name:` override path is correct (`compile.rs:564-565`). Confirmed end-to-end: a model `FROM smelt.sources.raw.users` compiles to `FROM raw.users`. → **BUG-033** (spec-vs-code conflict; sources are external, so the last-two-segment convention is arguably the *correct* behaviour and the spec/docs are wrong — recommend amending the spec).
- ❌ **`MalformedSource` diagnostic has zero producers.** Spec §"Diagnostic codes" mandates `MalformedSource` (Error) when a source `.yml` parses as YAML but violates the shape (missing `columns`, `materialization:` present, malformed column entry). The code is *defined* (`crates/smelt-db/src/diagnostics_types.rs:21`) and string-mapped in the LSP (`crates/smelt-lsp/src/backend.rs:235`) but **never emitted anywhere**. → **BUG-032**.
- ⚠️ **`SourceTypeError` is emitted only for the legacy aggregate `sources.yml`.** Spec §"Diagnostic codes" defines `SourceTypeError` (Error) for an unrecognised `columns[].type`. The emitted instance (`crates/smelt-db/src/lib.rs:1451`, fed by `sources_type_errors` in `queries/project.rs:246-306`) reads the legacy aggregate `project.sources_yaml(db)` — **not** the per-entity source YAMLs discovered by `discover_source_infos`. A bad type in a per-entity source (`models/sources/raw/x.yml`) is swallowed, not flagged. → folded into **BUG-032**.
- ❌ **`columns[].type` is "required" in the spec but defaults to `Text` in the parser.** Spec §"Source YAML shape" marks `columns[].type` Required = `yes`. `parse_source_yaml` maps a missing `type:` to `DataType::Text` (`sources.rs:188`) — a column with a typo'd/omitted type silently gets a wrong contract instead of `MalformedSource`. → folded into **BUG-032** (minor sub-case; dead-ended by the same swallow).
- ⚠️ **`name:` format check accepts >2 dotted segments.** Spec requires `<schema>.<table>` (two parts); `sources.rs:177-181` only checks "contains a dot, not leading/trailing" so `name: a.b.c` is accepted. Minor; folded into **BUG-032**.

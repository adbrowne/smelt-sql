- ⚠️  `unstable_schema` — listed in spec Surface table as a known key, but absent from the `Config` struct. Handled by separate pure text helper `parse_unstable_schema_flag`. The spec's "Unknown keys" warning rule doesn't fire for it (because Config has no deny_unknown_fields). Implementation matches spec's explicit note ("The flag itself is parsed by a small text-based helper"), but the key is absent from the struct, creating a non-obvious boundary.

- ✅ `tags` — present in ModelConfig
- ✅ `target` — present in ModelConfig
- ❌ `timeseries` — present in ModelConfig (`pub timeseries: Option<TimeseriesConfig>`) but NOT in spec's model-config shape table. → BUG-059 (spec-gap)
- ❌ Docs-site (`smelt-yml.md` §"Incremental Configuration") shows `event_time_column`, `partition_column`, `granularity` as sub-fields of `incremental:`. These belong to the separate `timeseries:` key, not `incremental:`. The `IncrementalConfig` struct uses `#[serde(deny_unknown_fields)]`, so a user following the docs example would get a parse error. The `ModelConfig` struct does not have these fields; they silently vanish if written in smelt.yml. → BUG-058 (docs-gap, deferred — schema_evolution docs ahead of spec)

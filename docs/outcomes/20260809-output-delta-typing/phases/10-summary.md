# Phase 10 summary — Surface: explain edge delta types, degradation reasons, docs-site

## Shipped

- `build_maintenance_plan_report` (`crates/smelt-cli/src/explain.rs`) takes a new
  `edge_delta_types: &[(String, OutputDelta)]` parameter and renders a `delta type:` row inside
  each inbound edge's block, after its contract rows — `append-only within window` / `keyed
  upsert` / `general (degraded by: <reason>)`; an edge absent from the slice prints no row.
- `commands/explain.rs::explain_maintenance_plan` assembles that vector: model edges read
  `smelt_db::model_edges_for(...)`'s already-derived `ModelEdge.output_shape` (phase 9), source
  edges are seeded via `output_delta::SourceFacts::from_source_info` +
  `output_delta::seed_shape_for_source` over `find_source_info` (now `pub(crate)`/`pub`) — no
  re-derivation.
- The repair stanza's `affected-key discovery:` line now branches on `cell.key_scope`: a
  key-addressed `PerGroupRecompute` cell prints "group-grain fingerprint-sidecar diff over the
  upstream's own output table" instead of consulting `find_source_info` (which would find
  nothing — the trigger source is a model, not a declared source).
- `docs/specs/incremental_models.md` §Surface "CLI" describes the new row and the third
  discovery posture; the now-fully-closed Known Divergences entry ("still generic") is deleted.
- `docs-site/docs/reference/cli.md` gains an explanatory paragraph plus a golden-matching
  `delta type:` line in the sample output; `crates/smelt-cli/tests/fixtures/
  explain_show_sql_daily_events_golden.txt` and the generated web-analytics tutorial page
  (`deduplication.md`, via `python3 examples/web_analytics/generate_tutorial.py`) both updated
  to match.
- 6 new tests in `crates/smelt-cli/tests/explain_maintenance.rs`, all red→green: a clockless
  keyed-upstream model edge, a clocked append-only source edge (regression guard), a
  window-function-degraded model edge (naming the construct), an undeclared-mutation-profile
  source edge (fail-closed visible), an edge with no derivable verdict (absence stays absence),
  and the key-addressed cell's sidecar discovery line.

## Decisions

- Source-edge facts are built directly via `output_delta::SourceFacts::from_source_info` +
  `find_source_info` rather than routing through `smelt_db::queries::maintenance::source_facts`
  (a different, maintenance-layer `SourceFacts` type the plan's task 3 wording pointed at) —
  the two structs are not interchangeable; the direct construction mirrors the existing
  precedent in `smelt-db::lib.rs::model_own_source_facts`.
- New tests use two small purpose-built fixtures rather than reaching for existing example
  projects: `stage_dag(keyed_chain_dag())` (already generated by `smelt-maintenance-testkit`,
  reused as-is) for the keyed-upstream/sidecar cases, and one hand-authored tempdir project
  (`stage_delta_type_project`) covering the general/window-function, undeclared-mutation-profile,
  and absent-verdict cases in one staging call — no example workspace has all three shapes.

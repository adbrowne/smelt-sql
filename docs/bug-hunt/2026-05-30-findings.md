### BUG-005 — Sub-directory seeds unresolvable in the CLI run/explain path (asymmetric discovery)
- **Phase**: A3   **Feature(s)**: cli (architecture, seeds)   **Found via**: fixture (adversarial drive of `smelt explain`/`build` over `examples/ephemeral_demo`)
- **Severity**: major
- **Symptom**: `examples/ephemeral_demo` declares an ephemeral seed at `models/lookup/regions.csv` (sidecar `regions.yml`) and a model `region_report` selecting from `smelt.lookup.regions`. Both LSP gates assert the workspace is clean (`example_diagnostics::ephemeral_demo_no_diagnostics`, `example_workspaces::ephemeral_demo`), yet `smelt build`, `smelt run`, and `smelt explain [--json]` all fail: `Dependency resolution failed: Model 'region_report' references undefined model/source 'lookup.regions'` (exit 1). A shipped example demonstrating ephemeral seeds could not be built or explained from the CLI.
- **Root cause**: `crates/smelt-cli/src/logical_graph.rs:78` — `let seed_set: HashSet<String> = seeds.iter().map(|s| s.name.clone()).collect();` keyed the seed validation set by the seed's leaf `name` (`"regions"`). But model nodes and dependency strings are keyed by the **canonical dot-path** (`address_segments.join(".")`, e.g. `"lookup.regions"`; see `logical_graph.rs:137-144`, `:193-206`). `validate()` (`:247`) then checks `is_seed("lookup.regions")` against a set holding only `"regions"` → miss → "undefined". The CLI's dep-validation resolver thus diverged from the Salsa/LSP `resolve_ref_path`, which resolves sub-directory seeds by full address — the asymmetric-discovery bug class `CLAUDE.md` warns about. The existing `ephemeral_seed.rs` test missed it because it builds the resolver manually rather than driving the CLI discovery + graph path.
- **Spec rule**: architecture.md §Resolution ("`smelt.<path>` is the universal addressing scheme"; entities addressable by full path); cli.md Constraint #11 ("Argument resolution uses the same resolver as model SQL … there is no parallel leaf-only resolver in the CLI surface") and Constraint #10 (all CLI output canonical `smelt.<path>`).
- **Resolution**: code-fix
- **Regression test**: `crates/smelt-cli/src/logical_graph.rs::tests::test_subdirectory_seed_as_ref_target_validates` (unit, red-green confirmed — fails with the exact "undefined model/source 'lookup.regions'" error before the fix) + `crates/smelt-cli/tests/subdir_seed_resolution.rs::ephemeral_demo_subdir_seed_resolves_in_cli_path` (integration over the real `examples/ephemeral_demo` through `build_logical_graph`, closing the example-level asymmetric-discovery gap the gates missed).
- **Fix**: key `seed_set` by `address_segments.join(".")` (falling back to `name` when empty, mirroring the model `canonical_key` logic). Backward-compatible: top-level seeds have `address_segments == [name]`, so their key is unchanged. `iter_seeds()` now surfaces seeds by canonical path (Constraint #10).
- **Status**: fixed

### BUG-006 — In-model meta-language is LSP-clean but does not survive the CLI run/build pipeline
- **Phase**: A5   **Feature(s)**: meta_language (architecture, cli)   **Found via**: fixture (adversarial end-to-end drive of `smelt run`/`build` over shipped `examples/meta_*`)
- **Severity**: major
- **Symptom**: Multiple shipped, LSP-clean meta-language example workspaces fail when driven through the CLI run/build path, in two distinct ways:
  - `examples/meta_lists` → `smelt run` emits an un-elided empty spread to DuckDB: `Parser Error: syntax error at or near ".."` on `...[],`. The spec (§"Lists and spread", Surface + Semantics rule 7) requires `...[]` to elide itself and adjacent commas before SQL reaches the engine.
  - `examples/meta_hofs`, `examples/meta_polish` → `Dependency validation failed: Model '…' references undefined model/source 'config.var'` (from `smelt.config.var(...)`).
  - `examples/meta_workspace` → `references undefined model/source 'with_tag'` (from `smelt.models.with_tag(...)`).
  - A reflection function `coalesce_numeric(t) = smelt.columns_of(t) |> filter(fn c => c.is_numeric) |> map(fn c => COALESCE(c.name,0))` spread into a hand-authored model is inlined but emitted **verbatim** (the `...`, `|>`, `columns_of` are never meta-evaluated) → DuckDB `syntax error at or near ".."`.
  All of these workspaces pass `cargo test -p smelt-cli --test example_diagnostics` (LSP/Salsa path is clean); only the CLI run/build/explain path is affected. This is the BUG-005 asymmetric-discovery class, now systemic across the meta-language surface.
- **Root cause** (two classes, both confirmed by code inspection):
  - **Class 1 — CLI dependency validator mis-extracts meta accessors as model/source refs.** `crates/smelt-cli/src/logical_graph.rs:113-134`: the dependency filter skips only `Some("sources") | Some("functions")` namespaces (line 117) and strips a legacy `models` prefix (line 123-124). It does **not** exclude the meta-accessor namespaces `config.*` (so `smelt.config.var` → dep `"config.var"`), bare `columns_of` (→ dep `"columns_of"`), or `models.with_tag`/`models.all` (the `models`-prefix strip turns `smelt.models.with_tag` into dep `"with_tag"`). `extract_refs` (`crates/smelt-core/src/refs.rs:57-111`) emits **all** `smelt.<path>` call forms — meta accessors included — and the CLI consumes them unfiltered. The Salsa/LSP path explicitly excludes these meta accessors before dependency resolution (`crates/smelt-db/src/queries/function_diagnostics.rs:1083-1101`), which is why the example_diagnostics gate stays green.
  - **Class 2 — in-model meta-evaluation is never invoked in the run pipeline.** `crates/smelt-cli/src/commands/run.rs` delegates to `smelt_runtime::execute_project`, which expands **only** generator-emitted models (the W1–W4 Salsa pipeline in `crates/smelt-db/src/queries/project.rs::evaluate_generator`/`emitted_models`). Hand-authored models containing inline meta syntax (spread/HOF/`columns_of`/ternary) are passed to the compiler verbatim — there is no meta-expansion step for them. `examples/per_cohort_union` builds only because it routes everything through a `generates: models` generator (which IS expanded), not through in-model spread/HOF.
- **Spec rule**: §"Lists and spread" Surface ("Empty-list spread elides itself and its adjacent commas") + Semantics rule 7; §"Reflection"/§"Compile-time variables" (accessors are meta-only, never model refs); §"Two worlds, one program" ("After meta-evaluation, the Data-World CST handed to codegen contains no `ARRAY_LITERAL` and no spread node"). Architecture §Run Pipeline Parity (the gap is in the shared `execute_project`, so it affects CLI and UI identically).
- **Resolution**: needs-review (invariant / architectural — the holding fix touches `smelt-runtime`'s run pipeline)
- **Options**:
  - (a) **Wire in-model meta-expansion into `smelt_runtime::execute_project`** so hand-authored models with spread/HOF/`columns_of`/ternary are meta-evaluated before codegen (the Class-2 fix), AND add the meta-accessor namespaces to the CLI dependency filter at `logical_graph.rs:117` — or, better, exclude meta accessors at the shared `extract_refs` boundary so CLI and Salsa agree (the Class-1 fix). Add an end-to-end gate (`smelt build` over `meta_lists`/`meta_hofs` asserting correct DuckDB output) — currently no test drives these examples through the CLI. Spec-faithful but non-trivial and pipeline-touching.
  - (b) **Scope the shipped `meta_*` examples as LSP-only demonstration fixtures** (matching `meta_columns`, whose source has no backing data and was never meant to run), and add a §Known Divergence to `meta_language.md` stating in-model meta-expansion in the run pipeline is not yet wired (only `generates: models` generators expand end-to-end). Lower effort; documents reality; defers the codegen work.
  - *Recommendation*: **(a)** for Class 1 at minimum (the CLI/Salsa resolver divergence is a clear correctness bug and the exact asymmetric-discovery class CLAUDE.md warns about), gated behind a human decision on Class 2's scope. Class 1's isolated fix was **not** applied autonomously because (i) on its own it does not make any example buildable (Class 2 still blocks with a DuckDB syntax error, so a "won't hold" end-to-end regression test is impossible), and (ii) excluding the `models.with_tag` form collides with the legacy `smelt.models.<leaf>` model-namespace strip and needs a resolver-design call.
- **Regression test**: _none yet_ — deferred to the human pass. The natural shapes: a `logical_graph.rs` unit test asserting `smelt.config.var(...)`/`smelt.columns_of(...)` are not emitted as model deps (Class 1, would hold), and an end-to-end `smelt build` test over `meta_lists` asserting `...[]` elision in the materialised output (Class 2, only passes after the pipeline fix).
- **Status**: needs-review

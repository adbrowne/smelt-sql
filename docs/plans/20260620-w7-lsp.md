## Goal

Bring the LSP's file-watching, diagnostic republication, and rename behaviour into line with the reviewed spec:

- **D-48 (major).** The watched-file globs are hardcoded `**/models/**/*.py` and `**/functions/**/*.sql` (`backend.rs:1377-1402`), but discovery is now universal (any non-excluded `.sql` is a model/function) and `paths:`/`exclude` are configurable. Model `.sql` files aren't watched at all — an external `git checkout` that edits a model is missed. Derive the watched set from the loaded project's discovery rules (all discoverable `.sql` not ruled out by `exclude`, wherever they live; plus `.py` model files), and **republish** diagnostics for the changed file **plus every file whose Salsa-derived diagnostics changed** (≥ all open files in the same project) — an upstream edit must refresh downstream diagnostics, not just the edited file.
- **D-49 (major).** Column rename must be **rooted at the resolved definition site**, rewrite all transitive consumers, terminate propagation at an `AS` re-alias, and propagate through `SELECT *` chains; and a **source** column (an externally-managed table) must **refuse** `prepare_rename` with an explanatory message — renaming a source column only rewrites the `.yml` declaration while every runtime query against the real external table breaks.
- **D-56 (minor).** Hover currently surfaces the file's last-modified timestamp, contradicting the meta-config hover's "No clock" determinism invariant (and risking registering mtime as a Salsa input). Drop mtime from hover.

## Deferred during implementation

(Append-only.)

- **P2 conservative superset.** `publish_all_diagnostics()` publishes for all tracked files across all projects in the server. The spec says "≥ all open files in the same project." The cross-project blast is negligible in a typical single-workspace session; the precise per-project scoping was deferred as it would require filtering `tracked_files` by project root, adding complexity.
- **`did_open` single-publish gap.** When a `.sql` file is first opened via `textDocument/didOpen`, only that file's diagnostics are published (`publish_diagnostics(uri)`). Upstream edits that were already in the DB remain correctly republished via `publish_all_diagnostics()` on subsequent `did_change`; the `did_open` gap is pre-existing and out of scope for W7.

## Design decisions (resolved — do not re-litigate)

| Dec | One-line contract (the spec is authoritative) |
|-----|-----------------------------------------------|
| **D-57** | The `cardinality:` frontmatter string maps to `Cardinality` via **exact spelling only**: `"1:1"` → `OneToOne`; **any other string** (including `"1:N"`, `"N:1"`, `"N:M"`, `"one_to_one"`, mixed-case `"1:1 "`, unrecognised tokens, or empty string) → a non-`OneToOne` value that **never enables `EliminateUnusedLeftJoin`**. Fail-safe direction: when in doubt, do not elide. No error is emitted for an unrecognised cardinality string — the join is simply kept. |

**Why the fail-safe direction matters.** `EliminateUnusedLeftJoin` is the only soundness-bearing rewrite in v1. Mapping an unrecognised string to `OneToOne` (optimistic default) would silently enable an unsound elision when an author misspells or uses an alternate spelling. Mapping it to `OneToMany` (conservative default) keeps the join and produces a correct (if unoptimised) result. The asymmetry is intentional and normative per Semantics rule 8.

**Implementation shape.** In `crates/smelt-logical/src/logical.rs`, add:

```rust
/// Maps the raw `cardinality:` frontmatter string to the [`Cardinality`] enum.
///
/// Normative, fail-safe (Semantics rule 8, D-57):
/// - `"1:1"` → [`Cardinality::OneToOne`] (the only value that enables elision).
/// - Any other string → [`Cardinality::OneToMany`] (conservative; join is kept).
///
/// No error is emitted for unrecognised strings — the fail-safe is silent.
pub fn cardinality_from_str(s: &str) -> Cardinality {
    if s == "1:1" {
        Cardinality::OneToOne
    } else {
        Cardinality::OneToMany
    }
}
```

Then, at every `LogicalNode::LeftJoin { cardinality: … }` construction site that draws from a `JoinSpec.cardinality` string, replace the direct value with `cardinality_from_str(&spec.cardinality)`. If no such construction site exists yet in production code (i.e., `LogicalNode::LeftJoin` nodes are only built in tests with hardcoded `Cardinality::` values), the mapping function still lands here as the normative implementation, and the test fixtures in `show_plan.rs` exercise the end-to-end path from frontmatter string to rule gate.

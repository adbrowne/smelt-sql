### Phase P1: Verify + lock nested-expansion Caller-tag-preservation (D-54)

**Goal.** Confirm the current `clone_with_tag` implementation already satisfies the D-54 invariant, then lock it with a regression test so the invariant cannot silently break. The spec (`expansion.md` line 77) states: "Tags are assigned once, relative to the original source; nested expansion leaves prior tags intact." The code in `crates/smelt-planner/src/logical_plan_rules.rs` lines 482–488 already preserves existing tags — when `clone_with_tag` encounters a `LogicalNode::Tagged { tag: existing, inner }`, it keeps `existing` and only recurses into `inner` without overwriting the tag. This phase is **verify-and-lock**, not a behaviour change.

**Critical files.**
- `crates/smelt-planner/src/logical_plan_rules.rs` — `clone_with_tag` (lines 411–501), `build_expanded_call` (lines 344–390), `splice_body` (lines 403–409).
- `crates/smelt-planner/tests/phase41_body_splice_tests.rs` — existing provenance tests (extend here).

**Test idea.** Write a test that builds a two-level expansion tree: a root model calls `A` (tagged `Callee(A)`), and `A`'s body contains a node already tagged `Caller`. Run `splice_body` with `ProvenanceTag::Callee(B)` on the result and assert that the inner `Caller`-tagged node's tag is unchanged (still `Caller`, not `Callee(B)`). This pins the "no re-tag on nested expansion" rule. Use the existing `contains_tag` helper in `phase41_body_splice_tests.rs`.

**Note on spec vs code span representation.** `expansion.md` writes `Caller(span)` and `Callee(fn_id, span)`, but the current `ProvenanceTag` enum has `Caller` (no span) and `Callee(FnId)` (no span). This is a pre-existing known divergence (span fields not yet wired); do **not** add span fields in this phase. The D-54 invariant concerns tag preservation, not span completeness.

**Commit.** `test(planner): lock nested-expansion Caller-tag-preservation invariant (D-54)`

### Phase P2: Fix record overlay — shallow replace, not deep recursive merge (D-55)

**Goal.** Change `merge_values` in `crates/smelt-db/src/loader.rs` so that when the record schema has a nested-record field, the overlay value **replaces the base value wholesale** rather than recursively merging. The spec (`meta_config_loading.md` line 57) is explicit: "an overlay's value for a field replaces the base's value for that field wholesale — including a nested record value, which is replaced as a whole, not recursively blended." The current implementation at lines 1165–1177 calls `merge_values(bv, ov_val, field_schema)` for every overlay field — for a nested-record field this is a deep recursive merge, which is wrong.

**Fix shape.** In the `SmeltType::Record` branch of `merge_values`, replace the `merge_values(bv, ov_val, field_schema)` recursive call with a simple `ov_val` (overlay wins wholesale). The field schema is only needed for dispatch at the root level (record/list/map); nested records are replaced as atomic values. The `merge_values` doc comment must also drop the phrase "merged recursively" and replace it with "overlay field replaces base field wholesale".

**Critical files.**
- `crates/smelt-db/src/loader.rs` — `merge_values` function (lines 1152–1202) and its doc comment.
- `crates/smelt-db/src/loader.rs` — test `overlay_record_root_deep_merges_overridden_field` (line 1634): rename to `overlay_record_root_shallow_replaces_overridden_field` and confirm its assertions still hold (flat-field override is the same for both shallow and deep; that test was mis-named but not mis-testing).

**Test idea.** Write a test with a schema containing a nested record field: `{ meta: { env: Text, version: Integer }, threshold: Integer }`. Base has `meta: {env: "dev", version: 1}` and `threshold: 100`. Overlay has `meta: {version: 2}` (partial nested record). With deep merge the result would be `meta: {env: "dev", version: 2}` (merged). With shallow replace the result should be `meta: {version: 2}` (overlay replaces base meta wholesale, so `env` is absent). The test asserts the shallow-replace outcome. This is the canonical D-55 discriminator.

**Commit.** `fix(db): record overlay is shallow replace, not recursive deep merge (D-55)`

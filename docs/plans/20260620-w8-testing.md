## Spec mismatch (human triage) — D-45

**Status**: the committed `testing.md` §"CTE-level tests" (lines 120–128) matches the D-45 custom answer: *"substitutes the model's external dependencies (the `smelt.<path>` refs reachable from the target CTE's dependency chain) with mock data from `inputs`"* and *"`inputs` keys … are the model's `smelt.<path>` dependencies, never internal CTE names."*

**Current code divergence**: `compile_cte_test` in `crates/smelt-cli/src/test_compiler.rs` mocks the **target CTE's direct internal CTE dependencies** (other CTEs in the model's `WITH` clause). It does not walk the external `smelt.<path>` refs reachable from the target CTE's chain. This is a significant behavioral gap:
- The spec says: extract the target CTE + its transitive internal CTE chain; substitute the **external `smelt.<path>` refs** that the chain reaches; run internal CTEs as-written.
- The code today: extracts only the target CTE; mocks its **internal** CTE dependencies; errors if a dependency is not in `inputs`.

**No triage needed** — testing.md is clear and consistent with the user's D-45 answer. P3 implements the spec as written.

### Phase P1: `inputs` keys use dot-separated bare address path (D-42)

**Goal.** The public `inputs:` YAML key is the bare address path with **dot separators** (`orders`, `silver.orders`), matching the spec §"`test:` frontmatter key" and Constraint 4. Internally, the test compiler continues using `_`-joined identifiers as the CTE name in generated SQL (SQL identifiers cannot contain `.`). The fix is a translation layer: `silver.orders` → lookup key `silver.orders` in the YAML map → CTE name `silver_orders` in SQL.

The current code at `test_compiler.rs:462` joins segments with `_` and uses the same `_`-joined name as the `inputs` lookup key (line 495), so a user who writes `silver.orders:` in their `inputs:` map gets a miss and an empty CTE. After this phase, the lookup key matches what the user writes.

**TDD tests (write first):**
- `crates/smelt-cli/tests/test_inputs_key_form.rs::inputs_dot_key_resolves` — a test with `inputs: { "silver.orders": [...] }` on a model that references `smelt.silver.orders`; verify the mock rows are injected (not an empty CTE).
- Unit test in `test_compiler.rs` asserting that `compile_whole_model_test` with key `"silver.orders"` uses those rows for the `silver_orders` CTE and does not substitute an empty CTE.

**Implementation.** In `compile_whole_model_test_inner`, at the mock-CTE-build loop (line 494): the CTE name is `segments.join("_")` (already derived); the `inputs` lookup key is `segments.join(".")`. Change `inputs.get(ref_name)` to `inputs.get(&segments.join("."))`. Apply the same translation in `compile_cte_test` (which is being rewritten in P3 anyway — leave the fix here for the whole-model path and carry it into the P3 rewrite).

**Commit.** `feat(cli): test \`inputs\` keys use dot-separated bare address path (D-42)`

### Phase P2: DECIMAL exact-compare path + decimal-string coercion (D-44)

**Goal.** Two linked changes, both implementing the user's chosen option B (risk-flagged, non-recommended):

1. **Coercion**: a YAML string value that looks like a decimal number (contains a `.`, no exponent, parseable as a finite decimal) is emitted as `CAST('300.00' AS DECIMAL)` in the generated SQL, distinct from the Float path. This is the "decimal string" coercion row in the spec's YAML→SQL type table (testing.md §"YAML value → SQL type coercion", row: `Decimal string ('300.00', …) → DECIMAL`).

2. **Comparison**: when the actual Arrow column type for a column is `Decimal128` (or any `DataType::Decimal*`), the comparison uses **exact numeric equality** — no `1e-6` tolerance. The `1e-6` path continues to apply to `Float32`/`Float64`/integer actuals. This requires threading Arrow's `DataType` into the comparison so `values_match` can branch on type.

**Risk note (reviewer scrutiny required).** The current `batches_to_rows` stringifies values before comparison; `values_match` has no schema information. To support type-aware comparison, the comparison path must be refactored: either pass the Arrow `Schema` alongside the rows, or introduce a typed value enum alongside the string map. Choose the minimal surface: passing `&Schema` into `compare_rows` and resolving column types by name is the smallest change. The reviewer must check the refactor does not regress the float-tolerance path.

**TDD tests (write first):**
- `crates/smelt-cli/tests/test_decimal_compare.rs::decimal_string_coerces_to_decimal_cte` — a test with an `expect` row `{total: '300.00'}` and a model that returns `SUM(amount)` over a DECIMAL column; verify the test passes (exact match) and the generated SQL casts the expected to DECIMAL.
- `…::decimal_no_float_tolerance` — expect `'300.001'`, actual `300.00`; assert the test **fails** (tolerance does not apply).
- `…::float_tolerance_unchanged` — expect `1.0000001`, actual `DOUBLE` column `1.0`; assert the test **passes** (tolerance still applies to FLOAT/DOUBLE).
- Unit test: `is_decimal_string("300.00")` → true; `is_decimal_string("3.14e2")` → false; `is_decimal_string("42")` → false.

**Commit.** `feat(cli): DECIMAL test comparison is exact; decimal-string coerces to DECIMAL (D-44)`

### Phase P3: CTE-level test mocks external `smelt.<path>` deps, not internal CTEs (D-45)

**Goal.** Rewrite `compile_cte_test` in `test_compiler.rs` to match the spec §"CTE-level tests":

1. Extract the **target CTE** and the transitive set of **internal CTEs it depends on** from the model's `WITH` clause.
2. Identify the **external `smelt.<path>` refs** reachable from that internal chain (refs that appear in any of the included CTEs' bodies).
3. Substitute those external refs with mock data from `inputs` (using dot-key translation from P1).
4. Build a standalone SQL query: `WITH <mock_external_CTEs>, <internal_CTE_chain> SELECT * FROM <target_cte>`.

The current `compile_cte_test` extracts only the target CTE's body and mocks its **direct internal CTE dependencies**, erroring if any are not in `inputs`. After this phase, internal CTEs run as-written; only external `smelt.<path>` refs are in `inputs`.

**TDD tests (write first):**
- `crates/smelt-cli/tests/test_cte_level.rs::cte_test_mocks_external_deps_not_internal_ctes` — a model with `WITH cleaned AS (SELECT … FROM smelt.raw_orders), agg AS (SELECT … FROM cleaned)` and a test targeting `target_cte: agg`; `inputs` provides `raw_orders` rows (the external dep); verify the test compiles correctly and `cleaned` runs as-written (not mocked).
- `…::cte_test_inputs_keys_are_model_deps_not_cte_names` — same model; `inputs` key `"cleaned"` (an internal CTE name) should produce an `UnknownTestInput` warning (it is not a `smelt.<path>` dep); the test should still run against the external dep if that is provided.
- `…::cte_test_transitive_external_deps_reachable` — a deeper chain: `WITH a AS (SELECT … FROM smelt.source), b AS (SELECT … FROM a), c AS (SELECT … FROM b)`; targeting `c` with `inputs: {source: [...]}` should work (transitive external dep resolved through the chain).

**Implementation.** Replace `compile_cte_test` with a new implementation:
- Use `extract_ctes` to get all CTEs and their internal dependencies.
- BFS/DFS from `target_cte` through internal CTE dependencies to collect the transitive internal chain.
- Scan each internal CTE's body for `SmeltPathRef` nodes (external refs); collect them.
- Build mock CTEs for those external refs from `inputs` (dot-key → `_`-joined CTE name).
- Emit: `WITH <mock_external_ctes>, <internal_chain_ctes_in_topo_order> SELECT * FROM <target_cte>`.

**Commit.** `feat(cli): CTE-level test mocks external model deps, not internal CTEs (D-45)`

### Phase P4: `UnknownTestInput` diagnostic for unmatched `inputs` keys (D-43) + close-out

**Goal.** Implement the fail-loud discipline for unmatched `inputs` keys (testing.md §"Whole-model tests", §"Constraints & Invariants" C4): every key in `inputs` must match a compiled dependency of the model under test (a `smelt.<path>` ref actually present in the model). An unmatched key is reported as `UnknownTestInput` and fails the test rather than silently becoming an unused mock CTE.

After P1, the lookup is dot-key → `_`-joined CTE name. An `inputs` key that does not appear in `ref_names` (the set of `smelt.<path>` refs found in the model) is unmatched. Surface this as a `TestError::CompilationError` (or a new `TestError::UnknownTestInput` variant) with a message naming the unmatched key and the model's actual dependencies.

Apply the same check in the P3-rewritten `compile_cte_test`: an `inputs` key that is not a reachable external `smelt.<path>` dep of the target CTE's chain is `UnknownTestInput`.

**TDD tests (write first):**
- `crates/smelt-cli/tests/test_inputs_key_form.rs::unknown_inputs_key_fails_loudly` — a test with `inputs: {order: [...]}` on a model that references `smelt.orders` (typo: `order` vs `orders`); assert the test **fails** with a diagnostic naming `"order"` as unknown and listing `"orders"` as the actual dep.
- `…::matched_inputs_key_passes` — `inputs: {orders: [...]}` on the same model; assert no unknown-key diagnostic.
- `…::cte_test_internal_cte_name_is_unknown_key` — (from P3) `inputs: {cleaned: [...]}` on a CTE-level test where `cleaned` is internal; assert `UnknownTestInput` for `"cleaned"`.

## Goal

Make `name:` in per-entity source YAMLs **target-aware** per `docs/specs/sources.md` §"Target-aware `name:` override":

- **Literal form** — `name: raw_cdc.users` applies the same `<schema>.<table>` to every target (current behaviour, preserved).
- **Per-target map form** — `name: { dev: raw_cdc_dev.users, prod: raw_cdc.users }` picks the entry matching the active `--target`; targets without an entry fall back to the default mapping.
- A map key that names no declared target, or a map value that is not `<schema>.<table>`, is a `MalformedSource` error.

The literal form is the all-targets shorthand; semantically it is a map whose single value applies to every target.

## Design decisions (resolved — do not re-litigate)

| Decision | Settled choice | Notes |
|----------|---------------|-------|
| **D-35: `name:` override shape** | **B — per-target map** | User's choice; **NOT the recommended option.** Option A (table-only override, schema always from active target) was simpler and the recommended path. This choice trades simplicity for power — a per-target map lets the *schema* differ per environment. **Risk-flagged in the master plan:** if target-precedence semantics (which target wins when multiple match? what if `--target` is absent?) are underspecified for a real case this plan hits, **block for a human call rather than guessing.** Reviewer must apply extra scrutiny here. |
| Fall-through on missing map key | Default mapping | A target with no map entry falls back to `<target_schema>.<address-path-joined-by-_>`. The map only overrides the targets it names. Spec §"Target-aware `name:` override" resolution rule 2. |
| Literal form is shorthand | Yes | `name: raw_cdc.users` behaves identically to `name: { every_target: raw_cdc.users }` but is accepted as a plain string value. The YAML parser must accept both YAML string and YAML mapping at the `name:` key position. |
| Target names must be declared | Yes, hard error | A map key that names no declared target is `MalformedSource`. Validation happens at YAML-load time so the LSP surfaces the error without executing the project. |

### Phase P1: `SourceNameOverride` — parse literal and per-target-map forms

**Goal.** Introduce a `SourceNameOverride` enum in `smelt-core/src/sources.rs` with two variants: `Literal(String)` (the existing all-targets string) and `PerTarget(BTreeMap<String, String>)` (the per-target map). Update `RawSourceYaml::name` to deserialise either YAML form using `#[serde(untagged)]` or a custom visitor. Validate each map value as `<schema>.<table>` format; emit `SourceError::InvalidNameOverride` for bad values. Preserve the existing `InvalidNameOverride` error for bad literals. Update `SourceInfo::name_override` from `Option<String>` to `Option<SourceNameOverride>`. All existing tests in `crates/smelt-core/tests/source_yaml.rs` must still pass (the literal form is unchanged semantically).

**Key files.** `crates/smelt-core/src/sources.rs` — `SourceNameOverride`, `RawSourceYaml`, `SourceInfo.name_override`, `SourceError::InvalidNameOverride`.

**Tests to write first (in `crates/smelt-core/tests/source_yaml.rs`):**
- `per_target_map_parses` — a source YAML with `name: { dev: raw_dev.users, prod: raw.users }` parses to `SourceNameOverride::PerTarget({"dev": "raw_dev.users", "prod": "raw.users"})`.
- `per_target_map_value_invalid_format_is_error` — a map value without a dot (e.g. `dev: nodot`) is `SourceError::InvalidNameOverride`.
- `literal_still_parses` — `name: raw_cdc.users` parses to `SourceNameOverride::Literal("raw_cdc.users")` (regression guard for existing form).

**Commit.** `feat(core): parse target-aware name: override in source YAML (D-35)`

### Phase P2: `SourceInfo::db_name_for_target` — resolve against the active target

**Goal.** Replace (or supplement) `SourceInfo::db_name(&self, target_schema: &str)` with `SourceInfo::db_name_for_target(&self, target_name: &str, target_schema: &str) -> String`. Resolution rules per `sources.md` §"Target-aware `name:` override":

- `SourceNameOverride::Literal(s)` — return `s` verbatim (any target, same as today).
- `SourceNameOverride::PerTarget(map)` — look up `target_name` in the map; if found return that `<schema>.<table>` verbatim; if absent return the default mapping (`<target_schema>.<address_segments.join("_")>`).
- `None` — default mapping.

Keep the old `db_name(&self, target_schema: &str)` as a deprecated shim that calls `db_name_for_target("", target_schema)` so callers that don't yet pass a target name compile without breakage (they'll use literal-form or default-mapping behaviour, which is correct for the common case).

**Key files.** `crates/smelt-core/src/sources.rs` — `SourceInfo::db_name_for_target`.

**Tests to write first (in `crates/smelt-core/tests/source_yaml.rs`):**
- `per_target_map_resolves_matching_target` — `PerTarget({"dev": "raw_dev.u", "prod": "raw.u"})`, `target_name="dev"` → `"raw_dev.u"`.
- `per_target_map_falls_back_on_missing_target` — `PerTarget({"prod": "raw.u"})`, `target_name="dev"`, `target_schema="main"`, `address_segments=["sources","raw","users"]` → `"main.sources_raw_users"`.
- `literal_ignores_target_name` — `Literal("raw_cdc.u")`, any `target_name` → `"raw_cdc.u"`.

**Commit.** `feat(core): resolve per-target source name override against active target (D-35)`

### Phase P3: Thread active target through runtime; end-to-end test

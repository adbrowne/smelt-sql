## Context

The 2026-06-12/13 spec review resolved 58 design decisions across 8 themes and committed them to 28 specs under `docs/specs/`. The decisions doc tags each with an implementation wave (`impl→ D-resolve`, `D-diag`, `D-types`, `D-misc`, `D-cli`, `D-incr/planner`). This master sequences that code work into dependency-ordered **waves** (crate order: `smelt-types`/`smelt-parser` → `smelt-core` → `smelt-db` → `smelt-logical`/`smelt-planner` → `smelt-runtime` → `smelt-cli`/`smelt-lsp`), keystone-first.

**Strategy (decided 2026-06-13):**
- **Just-in-time scaffolding** — only the current wave's sub-plan exists in the registry at any time; the next is scaffolded when the loop reports `<<MASTER_EXHAUSTED>>`. Avoids over-committing plan detail that early waves may reshape.
- **Keystone-first** — W1 (D-resolve, discovery/addressing) goes first; CLI/LSP/Python waves depend on the new addressing model.
- **Isolate the riskiest** — decisions that chose the higher-risk option over the review's safe recommendation get their **own** standalone sub-plan with extra review (so a block there doesn't stall a wave). Primary: **D-24** (fully-interleaved Python↔SQL eval). Secondary flags carried into their waves: **D-35** (per-target source name map), **D-44** (exact DECIMAL compare), **D-07** (mint `ColumnTypeUnresolved` live).

**Out of scope** — `↔R1` cumulative_aggregate and `↔R2` incremental_models internals (D-11, D-51, the incremental halves of D-52/D-57) land with those separate spec rewrites. Pure-prose spec cleanups already committed in the review (D-03, D-10, D-12, D-13, Appendix-A wording-only items) carry no code obligation.

## Context

Pipe SQL gives smelt the BigQuery/Databricks FROM-first `|>` authoring form, where evaluation order equals lexical order (`docs/specs/pipe_sql.md` §Design — "Scope-flows-forward is the whole point"). Per §Design the pipe glyph is reused and disambiguated by parse position from the meta-language pipe, and pipe queries are kept as first-class CST nodes through analysis and **lowered to standard SQL at the `smelt-dialect` printer** — the same seam that already rewrites `QUALIFY` → subquery for backends that lack it. No backend advertises native pipe support yet, so the only emitted form is lowered standard SQL (§Semantics — "Native passthrough").

## Scope

### In scope (spec coverage)
- §Surface "Pipe query form" / "Pipe-mode trigger" — FROM-first parse trigger after optional leading `WITH`.
- §Surface "Pipe operators" — the full supported operator set: `WHERE`, `SELECT`, `EXTEND`, `SET`, `DROP`, `RENAME`, `AS`, `AGGREGATE`, `ORDER BY`, `LIMIT`, `JOIN`, set ops, `DISTINCT`.
- §Surface "Deferred operators" / §Diagnostics — `PipeUnknownOperator`, `PipeOperatorUnsupported`, `PipeStageMalformed`; deferred operators (`PIVOT`/`UNPIVOT`/`WINDOW`/`CALL`/`TABLESAMPLE`/`ASSERT`) fail loud.
- §Surface "Where a pipe query may appear" — model body, subquery, CTE body.
- §Semantics "Stage model and scope" / "Token disambiguation" / "Lowering to standard SQL" / "Native passthrough" / "PostgreSQL parser oracle".
- §Constraints 1–5.
- User docs: a docs-site pipe-syntax guide page; `docs/specs/diagnostics.md` rows; spec References fill-in.

### Explicitly deferred
- **Native pipe emission** on BigQuery/Databricks/DuckDB-via-extension (§Known Divergences). The `supports_pipe_syntax` capability is added and wired, but every backend reports `false`; only lowered SQL is generated. Native passthrough output is not built.
- **SELECT-then-pipe form** (`SELECT … FROM … |> WHERE …`) — only the FROM-first form is accepted (§Known Divergences).
- **Per-operator native capability matrix** — `supports_pipe_syntax` stays whole-feature (§Known Divergences).

### Phase 1: Grammar spine — CST, AST, FROM-first trigger, stage parse

**Goal.** Parse a FROM-first pipe query into first-class CST nodes: a `PIPE_QUERY` containing a `FROM` entry followed by a chain of `PIPE_STAGE` nodes, each tagged with its operator. Recognise every operator keyword (supported and deferred) so the parser never silently drops a stage. No lowering and no schema inference yet.

**Pre-conditions.** None — this is the foundation. `|>` already lexes as a single `PIPE_ARROW` token (`crates/smelt-parser/src/lexer.rs:181`).

**TDD tests to write first.**
- `crates/smelt-parser/tests/pipe_query.rs::from_first_triggers_pipe_query` — a body `FROM orders |> WHERE status = 'paid'` parses to a `PIPE_QUERY` with a FROM entry + one `PIPE_STAGE(WHERE)`; assert the CST shape (kinds + nesting), no parse errors.
- `crates/smelt-parser/tests/pipe_query.rs::leading_with_then_from_first` — `WITH r AS (SELECT 1) FROM r |> LIMIT 1` parses as a `PIPE_QUERY` whose CTEs precede the FROM-first body.
- `crates/smelt-parser/tests/pipe_query.rs::select_body_is_not_pipe` — `SELECT 1 FROM t` still parses to `SELECT_STMT`, not `PIPE_QUERY` (trigger is bare-FROM only).
- `crates/smelt-parser/tests/pipe_query.rs::each_supported_operator_parses` — one stage per supported keyword (`WHERE/SELECT/EXTEND/SET/DROP/RENAME/AS/AGGREGATE/ORDER BY/LIMIT/JOIN/UNION/DISTINCT`) parses to a `PIPE_STAGE` tagged with that operator; assert the stage-kind marker.
- `crates/smelt-parser/tests/pipe_query.rs::unknown_operator_diagnostic` — `FROM t |> FROBNICATE x` yields `PipeUnknownOperator`.
- `crates/smelt-parser/tests/pipe_query.rs::malformed_stage_diagnostic` — `FROM t |> WHERE` (no predicate) yields `PipeStageMalformed`, anchored at the stage span.
- `crates/smelt-parser/tests/pipe_query.rs::deferred_operator_diagnostic` — `FROM t |> PIVOT(...)` yields `PipeOperatorUnsupported` with the spec's reason text.

**Implementation shape.** Add `PIPE_QUERY`, `PIPE_STAGE`, and per-operator stage-kind marker variants (follow the zero-width `EXPR_KIND_*` marker pattern, `syntax_kind.rs:299`) — **appended** to the `SyntaxKind` enum (Rowan order rule, `syntax_kind.rs:643`). Add AST wrappers (`PipeQuery`, `PipeStage`, accessors for stage kind + body) in `ast.rs`. In `parse_file`/`parse_select_stmt` (`smelt_ext.rs:53`, `select.rs:14`), detect "after optional `WITH`, the body is at `FROM_KW`" and dispatch to a new `parse_pipe_query` in a new `parser/pipe.rs`. `parse_pipe_query` parses the FROM entry by reusing `parse_from_clause` (`select.rs:268`), then loops on `PIPE_ARROW`, dispatching each stage by its leading keyword to a per-operator stage parser that reuses the existing clause grammar (e.g. the `WHERE` stage wraps the predicate grammar). Unknown keyword → `PipeUnknownOperator`; deferred keyword → parse into a `PIPE_STAGE` and emit `PipeOperatorUnsupported`; clause-grammar parse failure → `PipeStageMalformed`. Stage parsers must not crash on truncated input (error recovery at the next `|>` or stage end).

**Critical files (allowed to touch in this phase).**

- `crates/smelt-parser/src/ast.rs` — `PipeQuery`/`PipeStage` wrappers.

- `crates/smelt-parser/src/parser/select.rs`, `crates/smelt-parser/src/parser/smelt_ext.rs` — FROM-first dispatch.

### Phase 2: Passthrough lowering — capability flag, single-SELECT collapse, compat gap

**Goal.** Lower a pipe query built only from "passthrough/projection" stages (`FROM`, pre-aggregation `WHERE`, trailing `SELECT`, `ORDER BY`, `LIMIT`, `DISTINCT`) into a single standard `SELECT` at the dialect printer, gated on `supports_pipe_syntax = false`. **TDD tests to write first.**

### Phase 3: Per-stage scope threading + column-editing operators

**Goal.** Thread the running output schema stage-to-stage so a stage sees exactly the prior stage's columns, and implement `EXTEND`, `SET`, `DROP`, `RENAME`, `AS` — both their schema effect (type inference) and their lowering (re-projection, wrapping the prior query as a subquery when the projection was already fixed).

**Pre-conditions.** Phase 2 (passthrough lowering + scope baseline for `FROM`/`WHERE`/`SELECT`).

**TDD tests to write first.**
- `crates/smelt-db/tests/pipe_scope.rs::extend_column_visible_next_stage` — `FROM t |> EXTEND a + b AS s |> WHERE s > 0` resolves `s` against the EXTEND output (no undeclared-column diagnostic); inferred schema = input columns + `s`.
- `crates/smelt-db/tests/pipe_scope.rs::drop_then_reference_errors` — `FROM t |> DROP a |> SELECT a` raises the existing undeclared-column diagnostic anchored at the `SELECT` stage (§Semantics 2 — dropped columns leave scope).
- `crates/smelt-db/tests/pipe_scope.rs::rename_and_set_schema` — `RENAME old AS new` renames in scope; `SET c = c * 2` keeps the column, replaces its value/type.
- `crates/smelt-dialect/tests/pipe_lowering.rs::extend_wraps_prior_projection` — an `EXTEND` after a fixed projection lowers to `SELECT <new projection> FROM (<prior query>)` (§Semantics "Lowering" rule 4).

**Implementation shape.** New pure module `crates/smelt-db/src/type_inference/pipe.rs`: `infer_pipe_stage_output_schema(input_schema, stage, ctx) -> Vec<(String, TypedColumn)>` per the agent-mapped per-operator logic (EXTEND appends, SET replaces in place, DROP filters, RENAME maps, AS aliases the whole table). A driver folds stages, building a per-stage `TypeContext` whose visible columns are the running schema (clone-and-edit the FROM-scope `TypeContext`, `type_context.rs:19`), and feeds the final schema to the existing SELECT-validation path. Keep all of this pure; call it from the existing Salsa wrapper for `type_context`/schema inference (Salsa purity rule).

## Goal

Make two already-specified behaviours real, with the smallest correct change in each case:

- **BUG-042 (correctness, major — VERIFIED)** — the `cases` field has zero effect; property-based tests are never dispatched. `crates/smelt-cli/src/commands/test.rs:200-207` always calls `run_test` (one-shot) after compiling; it never branches on missing columns, never calls `find_missing_columns`, and never reaches `run_property_test`. The `cases` field (`crates/smelt-core/src/metadata.rs:57-59`, `pub cases: Option<u32>`) is read **only** inside `run_property_test` itself (`crates/smelt-cli/src/test_property.rs:359`), which has **no production caller** (only its definition at test_property.rs:332 + its own `#[cfg(test)]` test at test_property.rs:628). The supporting infra is complete and unit-tested: `find_missing_columns` (test_property.rs:80-179, via smelt_db type inference), random generation, per-iteration seeding, `augment_inputs`, and failure reporting with `failing_seed`/`failing_iteration`. Wire the **CTE path** so `cases` drives the property loop.
- **BUG-026 (correctness, minor — VERIFIED; ledger premise was WRONG)** — `week_start` accepts all seven weekdays where the spec types it `monday | sunday`. `crates/smelt-core/src/config.rs:206-216` defines a full 7-variant `Weekday` enum; `week_start: Option<Weekday>` (config.rs:364) admits any of them; `validate_timeseries` (`crates/smelt-core/src/metadata.rs:372-377`) checks only that `week_start` requires `granularity: week` (rule 6), **not** the value domain. The ledger's claim that week_start is "inert/unimplemented → DEFER" is **false**: week_start is live — `crates/smelt-cli/src/commands/run.rs:1420` passes `inc_ts.week_start` to `generate_partition_values`; `crates/smelt-cli/src/helpers.rs:111-128` (the `Granularity::Week` arm) uses it to **align** weekly partition boundaries; `crates/smelt-planner/src/python_bridge.rs:53-56` forwards it. A bogus `wednesday` silently produces Wednesday-aligned partitions. Reject `week_start ∉ {monday, sunday}` and correct the stale spec divergence.

## Design decisions (resolved — do not re-litigate)

- **BUG-042 scope is the CTE path only in this plan; whole-model omitted-column detection is a tracked follow-up, not built here.** `find_missing_columns` *requires* a `target_cte` — it walks the WITH clause and computes the omitted columns at the named CTE (test_property.rs:120-176). `run_property_test` already only computes `missing` when `target_cte` is `Some` (test_property.rs:353-357), else it would run `cases` *identical* iterations. For whole-model tests there is no CTE, so omitted-column detection has no anchor. Wiring the CTE path is ~20 lines in `commands/test.rs` (call `find_missing_columns` before/around compiling; if non-empty, dispatch to `run_property_test` with `cases.unwrap_or(<spec default>)`; add a `PropertyTestResult` print path in `helpers.rs`). Whole-model detection is documented as a Known-Divergence note in testing.md (P1) and a one-line ledger note (P4) — **not** implemented in this plan. If whole-model detection turns out to be required rather than deferrable, that phase **blocks** for a design call (see §"Block conditions").
- **BUG-026: the ledger's "inert field → defer" premise is corrected — week_start is live, so validate now.** The verified call chain (run.rs:1420 → helpers.rs:111-128 → python_bridge.rs:53-56) proves week_start already alters weekly partition alignment, so an unconstrained value is a real correctness hole today. Add the value-domain check now (option a): in `validate_timeseries`, after the `granularity: week` rule, reject `week_start ∉ {Monday, Sunday}` → `MalformedTimeseries`. The stale timeseries.md Known Divergence ("week_start not yet implemented") is therefore wrong and is corrected (P3), not preserved.
- **The week_start diagnostic surfaces in both LSP and build by construction.** Per BUG-024's fix (already FIXED, 2026-06-01), `MalformedTimeseries` is gated into the CLI build pipeline via the shared Error-severity gate, so a new `MalformedTimeseries` for a bad `week_start` will surface in both the LSP and the build. P2 must **double-check** BUG-024's gate actually covers this new emission site (the dual gate `example_diagnostics` + `example_workspaces` proves it); if the run pipeline still filters timeseries diagnostics to a subset, note that as a finding and surface it through the build path explicitly.
- **`cases` default.** When dispatching the property loop, use `cases.unwrap_or(<spec default>)` — read the default from testing.md §Semantics rather than hard-coding a magic number; if the spec leaves it unstated, that is an open question to record (see §"Open question"), not a silent guess.
- **No determinism regression.** The property loop is already seeded deterministically per iteration (`failing_seed`/`failing_iteration`, test_property.rs). The new dispatch must not introduce nondeterminism into the test suite: the red test asserts a *fixed* iteration count and a deterministic outcome. If wiring surfaces flakiness from random seeding that needs a determinism decision, **block** (see §"Block conditions").

5. **Record + commit.** Update the status-table row to `done` + date; commit and push tests + impl + (spec where listed) + table together. Emit `<<PHASE_COMPLETE>>` (or `<<ALL_DONE>>` on the last green phase).

## Block conditions (`<<PHASE_BLOCKED>>` — record and continue, no hard-stop)
When a phase hits a condition below, **do not halt**. Instead: (1) set the row to `blocked` with a one-line reason; (2) append a dated entry to §"Blocked phases" (phase id, reason/decision, candidate options); (3) restore the tree to a clean committed state; (4) commit + push; (5) emit `<<PHASE_BLOCKED>>`. The next iteration skips the blocked row.

Conditions:
- Wiring property dispatch surfaces flakiness from random seeding that needs a **determinism decision** not answered by this plan (e.g. the per-iteration seed is not actually stable across runs, or the suite goes flaky).
- Whole-model omitted-column detection turns out to be **required** (not deferrable to a follow-up) to make BUG-042's acceptance test green — i.e. the CTE-path wiring alone cannot satisfy the spec's behaviour for the realistic fixture.
- BUG-024's Error-severity gate turns out **not** to cover the new `week_start` `MalformedTimeseries` emission, and routing it requires a pipeline-design decision rather than a local fix.
- Pre-flight is red on **unrelated** breakage (not this phase's own target), or the tree can't be returned to green after the phase.

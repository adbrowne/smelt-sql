## Context

The release review found the docs-site has strong language/guide/tutorial coverage but **no production operations story**: nothing on deploying a project, running it under an orchestrator, what `.smelt/` state contains, or how to recover from a partial failure (blocker #10). Meanwhile W1–W3 are landing exactly those operational surfaces. This plan adds an operations trio (deployment, orchestration, state & recovery), then refreshes the existing `reference/cli.md` and getting-started pages to cover the new commands and flags.

## Scope

### In scope
- New `guide/deployment.md`, `guide/orchestration.md` pages + nav entries.
- New `reference/state.md` (state & recovery reference) + nav entry.
- Extending the existing `reference/cli.md` (it already covers all current commands per-command — do **not** restructure it) with the W1–W3 additions, and adding the two orphaned reference pages (`reference/diagnostics.md`, `reference/smelt-explain.md`) to nav.

- Blog-series content — separate programme, not docs-site.
- Any generated-from-clap CLI reference mechanism — none exists today; hand-maintained `reference/cli.md` stays; building a generator is out of scope.

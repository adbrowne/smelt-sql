# Security Policy

## Supported Versions

smelt is pre-1.0 and evolving rapidly. Security fixes are made against the
latest minor release; we do not backport fixes to older minor versions.

| Version | Supported          |
| ------- | ------------------ |
| 0.5.x   | :white_check_mark: |
| < 0.5   | :x:                |

## Reporting a Vulnerability

If you believe you've found a security vulnerability in smelt, please report
it privately rather than opening a public GitHub issue.

Email **brownie@brownie.com.au** with a description of the issue, steps to
reproduce, and any relevant logs or proof-of-concept code. We aim to
acknowledge reports within **5 business days** and will work with you to
understand, confirm, and fix the issue before any public disclosure.

## Data Handling and Telemetry

smelt does not collect or transmit usage telemetry or analytics of any kind.
All compilation, planning, and execution happen locally (or against the data
backends you configure) — nothing about your models, data, or usage patterns
is sent to smelt's maintainers or any third party.
